# Operations Runbook

This runbook is for local proof-of-work operation. It documents the commands and evidence needed to
demonstrate the service architecture without deploying it.

## Local verification bundle

Run the deterministic checks:

```bash
uv run ruff check .
uv run mypy src
uv run pytest
uv lock --check
uv build
uv run python scripts/export_openapi.py --check
uv run python scripts/phase6_security_check.py
uv run python scripts/phase6_drill_manifest.py
docker compose --profile search --profile storage --profile workflow --profile runtime config
```

The OpenAI smoke is optional because it spends provider credits:

```bash
uv run python scripts/openai_generation_smoke.py
```

It must print only the evidence state and citation-match boolean. It must never print the key.

## Malware scanning

Production worker settings require:

```bash
APP_MALWARE_SCANNER_COMMAND=clamscan
```

The adapter executes the command without a shell, scans a temporary downloaded source object, and
rejects return code `1` as malware. Return code `0` is clean. Any other return code means the scanner
is unavailable or misconfigured.

The container installs the scanner executable for proof-of-work. Hosted operation still needs a
malware-definition update process and scanner health monitoring before real private PDFs are allowed.

## Rate and spend controls

The answer endpoint can reject requests before retrieval or generation starts.

Settings:

```bash
APP_ANSWER_RATE_LIMIT_PER_MINUTE=30
APP_ANSWER_MONTHLY_TOKEN_BUDGET=500000
APP_ANSWER_ESTIMATED_OUTPUT_TOKENS=1200
```

The current implementation is an in-memory proof contract. A hosted system should replace the backend
with Redis or PostgreSQL storage so limits survive restarts and multiple API replicas.

## Local service start

Start local dependencies:

```bash
docker compose --profile search --profile storage --profile workflow up -d postgres redis opensearch localstack temporal
```

Run migrations against the local database with a migration identity:

```bash
APP_DATABASE_URL="$MIGRATION_DATABASE_URL" uv run alembic upgrade head
```

Run the API locally:

```bash
uv run uvicorn document_intelligence.api.app:create_app --factory --reload
```

Run the worker locally:

```bash
uv run python -m document_intelligence.worker.main
```

## Health checks

Liveness:

```bash
curl -fsS http://127.0.0.1:8000/health/live
```

Readiness:

```bash
curl -fsS http://127.0.0.1:8000/health/ready
```

In staging or production mode, readiness must return `503` if required settings or runtime packages
are missing. It may return setting names and safe runtime error messages. It must not return secret
values.

## Backup and restore proof path

No production backup exists yet. For local demonstration, use this shape:

1. Create a PostgreSQL dump from the local database.
2. Save the exact Git commit, migration revision, and Compose image versions.
3. Restore into a fresh local volume.
4. Run Alembic upgrade.
5. Run RLS probes and the test suite.
6. Save the output under ignored `artifacts/phase-6/`.

Do not claim production RPO or RTO until this is repeated against the real deployment platform.

## Reindex and rollback proof path

1. Start from an immutable document version.
2. Run ingestion with pipeline version `A`.
3. Publish search projection version `A`.
4. Run retrieval checks.
5. Run ingestion with pipeline version `B`.
6. Publish projection version `B`.
7. Roll back or delete projection `B`.
8. Confirm projection `A` or the expected empty state remains active.
9. Save OpenSearch alias and document-publication ledger evidence.

The manifest for these proof paths is generated by:

```bash
uv run python scripts/phase6_drill_manifest.py
```

## Incident checklist

For a leaked secret:

1. Revoke the credential.
2. Rotate the credential.
3. Audit provider logs for use during the exposure window.
4. Remove the secret from any file or artifact.
5. If the secret entered Git history, rewrite history and force-push only after explicit approval.
6. Record the incident and verification evidence in the private vault.

For a cross-tenant access bug:

1. Disable the affected route or feature.
2. Preserve logs and audit events.
3. Add a regression test that reproduces the isolation failure.
4. Fix the database, search, storage, cache, or workflow boundary that allowed the leak.
5. Verify all tenant-bound paths again.
6. Record affected objects and notification requirements before any public claim.

For model citation failure:

1. Disable answer streaming if invalid citations can reach users.
2. Preserve the prompt, opaque evidence IDs, generated draft, and validation errors without storing
   full private document text in public logs.
3. Add a deterministic answer eval.
4. Fix citation validation or repair behavior.
5. Re-run answer, retrieval, and OpenAI smoke checks.

## Stop conditions

Stop and do not claim readiness if:

- any tenant-isolation test fails
- readiness exposes a secret value
- model output can create filenames, page numbers, or citations directly
- uploaded bytes can enter parsing without server-side integrity verification
- a quarantined page can enter the search index
- a Docker or Compose change exposes local services beyond loopback without a deliberate deployment
  plan
